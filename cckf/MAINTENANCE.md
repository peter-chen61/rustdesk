# Maintenance and security reporting

Repository owner and proposed maintainer: [peter-chen61](https://github.com/peter-chen61). Release approval responsibilities and account MFA still require the owner's confirmation. The project is early-stage and has no claimed public adoption metrics.

Review changes to remote-access behavior, deployment configuration and release scripts before merging. Never commit credentials, private deployment profiles, signing keys, access tokens or organization-specific preset passwords. Third-party security and licensing changes must be evaluated before updating the pinned baseline.

If you discover a security issue, do not include credentials or private device information in a public pull request. Use the organization's existing private support contact. A dedicated public vulnerability-reporting channel has not yet been established; that is a release-readiness gap. Upstream RustDesk issues should follow upstream reporting guidance.

No public release or signing approval is created by this preparation branch. Maintainer review and the provider's response are required before presenting the project as ready for signed distribution.
